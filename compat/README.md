# AHK v2 conformance corpus

Run the same unmodified `.ahk` files with official AutoHotkey v2 on Windows and Keysharp on each target OS. The 14 fixtures cover arithmetic and precedence, short circuit evaluation, closures, references and defaults, variadic calls, classes and inheritance, arrays and maps, exceptions, control flow, Unicode, regular expressions, and isolated file I/O.

This is a small executable corpus, not a claim of complete language or macOS compatibility. Input hooks, hotkeys, GUI, clipboard, timers, permissions, Windows APIs, COM, registry and application automation are outside its coverage. Passing Windows results do not establish macOS behavior.

## Run

Python 3.10+; standard library only. Supply an existing executable by path. No engine download or auto-discovery occurs.

```powershell
python compat/run.py --engine ahk --executable C:/tools/AutoHotkey64.exe --engine-version 2.0.31 --output compat/reports/windows-ahk.json
python compat/run.py --engine keysharp --executable bin/Debug/net10.0-windows/Keysharp.exe --output compat/reports/windows-keysharp.json --baseline compat/reports/windows-ahk.json
```

```sh
python3 compat/run.py --engine keysharp --executable bin/Release/net10.0/Keysharp.dll --output compat/reports/macos-keysharp.json --baseline compat/reports/windows-ahk.json
python3 compat/compare.py compat/reports/windows-ahk.json compat/reports/macos-keysharp.json --output compat/reports/comparison.json
```

`.dll` files launch through `dotnet`; use `--dotnet /path/to/dotnet` to override the host. Set `--timeout 30` for slower compilation. Repeat `--case regex --case unicode` to select fixtures; comparison requires identical selected case sets. `--engine-version` is an optional label, not a detected version. Executable SHA256, OS release, architecture and Python version are recorded.

Each case runs in a fresh temporary working directory. Source bytes are copied unchanged. All fixtures declare `#Requires AutoHotkey v2.0`, `#ErrorStdOut` and `#Warn All, StdOut`; no fixture opens a dialog or manipulates user input. Stdin is closed, `KEYSHARP_DAEMON=0`, stdout and stderr are captured separately. There is a real per-process timeout, including compilation. On Windows a suspended child is assigned to a kill-on-close Job Object before it starts, so descendants are contained. On POSIX the child gets a dedicated process group. Both are cleaned up on success and timeout.

The harness executes trusted local fixtures; process groups and Job Objects are cleanup mechanisms, not a sandbox for untrusted scripts.

## Reports and comparison

Reports use `schema_version: 1`. `corpus_sha256` identifies the manifest, source and golden output bytes. `cases` are ordered by ID and include source/golden SHA256, expected stdout, actual stdout/stderr, exit code, duration, status and failure reasons. Duration and host/engine metadata are informational and are excluded from differential comparison.

- `pass`: exit code zero, empty stderr, valid UTF-8 and exact golden stdout.
- `fail`: output mismatch, warnings, runtime/compile errors, invalid UTF-8 or process launch failure.
- `timeout`: the deadline expired and the process tree was terminated.
- `unsupported`: the manifest excludes the current OS, or the official Windows AutoHotkey engine was selected on another OS. Runtime error text is never guessed to mean unsupported.

Only CRLF is normalized to LF. Trailing spaces, blank lines, BOMs, case, paths, error messages and Unicode are preserved. Invalid UTF-8 bytes are escaped in the report and cause failure. No platform-specific output is hidden.

`run.py` exits 0 only when every selected fixture passes and the optional baseline matches; 1 means any failure, timeout, unsupported case or comparison difference; 2 means invalid arguments, manifest or baseline. `compare.py` exits 0 only for matching, nonempty, complete case sets with all cases passing; 1 for differences and 2 for malformed reports. Equal failures do not count as conformance. Changed source/goldens and missing cases are rejected.

Golden files must first pass the official AHK v2 reference run. They are reviewable expectations, not output generated by the candidate engine. Add a new script and golden file to `corpus/manifest.json`; all three required directives are checked before execution.

## Local phases 1–5

`contract.json` fixes the AHK 2.0.31 target. `suite.py` runs all corpora sequentially and then three isolated lifecycle processes and one contained self-Reload. The original 14 cases remain available through `run.py`.

| Corpus | Cases | Purpose |
|---|---:|---|
| `corpus` | 14 | Original shared language/file checks |
| `phase15-symbols` | 7 | ASCII-only identifier folding and dynamic lookups |
| `phase15-map-conversions` | 6 | Map keys/mutations/enumerators, conversions and predicates |
| `phase15-stdlib` | 6 | Native memory, encodings, file loops, string pointers, simple regex escapes and IsTime |
| `phase15-regex-edge` | 1 | 28 escape/context observations; broader PCRE equivalence remains unproven |
| `phase15-enumerators` | 9 | Native metadata, arity, real VarRefs, binding and OwnProps getters |
| `phase15-native-windows` | 1 | Native Float return/output widening; Windows-only DLL requirement |
| `phase15-reload/run_reload.py` | 1 | Process replacement, OnExit and fresh timers |
| `phase15-runtime` | 9 | Timers, Critical, Pause, OnExit and hotkey option parsing/atomicity |
| `phase15-architecture` | 5 | Strict destruction/resource lifetime; unresolved GC mismatch |
| `phase15-runtime/run_processes.py` | 3 | Expected nonzero exit codes, OnError and continuation |

```powershell
python compat/suite.py --engine ahk --executable C:/tools/AutoHotkey64.exe --engine-version 2.0.31 --output-dir compat/reports/official
python compat/suite.py --engine keysharp --executable bin/Debug/net10.0-windows/Keysharp.exe --output-dir compat/reports/windows --baseline-dir compat/reports/official
```

Transfer `compat/reports/official` alongside the checkout to a local Mac, install the pinned dependencies, then run:

```sh
bash scripts/macos/bootstrap.sh
bash scripts/macos/verify-local.sh --baseline-dir /path/to/official
```

Run separately on Intel and Apple Silicon. `--skip-build` reuses a built executable. `--output-dir` selects the report directory. The script refuses non-macOS hosts and Rosetta. It preserves known failures as failures, collects host/build evidence, and runs the four Mac-only `getpid`, `strlen` , `qsort`/callback and Float return prototypes. Their C ABI expectations are not an official Mac AHK baseline; native execution remains pending.

The `macOS compatibility` workflow has an optional `extended` input for manual runs. It runs the full 62-case reference/comparison suite and the four Mac ABI prototypes, preserving reports as artifacts. Known object-lifetime failures still fail the audit; the Windows-only native fixture is reported unsupported on Mac. Normal push runs use the original 14-case corpus and curated NUnit tests. An extended run is expected to remain red until these gaps are resolved.

The lifecycle runner validates its expected stdout/stderr/exit code and baseline identity; the ordinary corpus continues to require exit code zero. Managed engine reports include hashes of `Keysharp*.dll`, including scripting components, because the apphost hash alone cannot identify runtime changes. Windows evidence does not validate native macOS behavior.

```sh
python -m unittest discover -s compat/tests -v
```

The harness unit tests launch small Python processes to verify real timeouts, process-tree cleanup, stderr, nonzero exits, normalization and strict report comparison. They do not test AHK compatibility; that requires running the `.ahk` corpus with the actual engines.

The Windows-native corpus is explicitly unsupported on Mac; it remains a visible Windows DLL requirement, rather than being counted as portable coverage. Reload uses a Python controller inside the existing process-tree container so the replacement stays alive after the initial script exits.
